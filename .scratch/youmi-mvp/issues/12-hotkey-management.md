## Comments

### 2026-10-14 — 实现说明

- **架构**：新增 `src-tauri/src/shortcuts.rs` 统一管理动作 ↔ 组合键绑定。`ShortcutBindings` 状态（动作 → 组合键 + OS 注册是否生效）被快捷键 handler（分发）与 `shortcut_list`/`shortcut_set` 命令（展示/改键）共享；lib.rs 三个硬编码 `*_HOTKEY` 常量与闭包常量比对移除。
- **持久化**：组合键以插件解析格式规范串（如 `alt+KeyV`，修饰键序 ctrl/alt/shift/super，主键为 KeyboardEvent.code）存前端共享的 `settings.json`（plugin-store，Rust 侧经 `StoreExt` 读写同一实例）；键 `shortcut.clipboard` / `shortcut.palette` / `shortcut.translate`。
- **改键流程**（`set_binding`）：解析 + 修饰键校验 → 内部互斥校验 → 注销旧（已注册才注销）→ 注册新 → 失败回滚旧注册（回滚也失败则注册状态如实降级为未注册）→ 成功才更新绑定表并落盘。与已注册现绑定同组合幂等成功；启动期注册失败的绑定重输同组合会真正重试注册。
- **启动**（`shortcuts::setup`）：存储组合键非法回退默认；手改设置造成内部冲突也回退默认，默认仍冲突则该动作本次启动不生效（日志可见）；注册失败仅降级日志，绑定标记未注册——设置页该行会显示「注册失败」警示，重新改键可重试。
- **设置页**：录制式改键（点击修改 → 截获下一次完整组合键，Esc 取消，纯修饰键等待主键）；成败都以后端列表 refetch 回显；原「呼不出剪贴板浮层？/翻译浮层？」两条静态提示行移除，占用排查指引并入快捷键行描述。
- **测试**：Rust 20 个（解析/互斥/回滚序列/幂等重试/启动回退/规范串对齐/注册状态展示，经 `ShortcutRegistrar`/`ShortcutSettings` 双 seam 假实现）+ 前端 7 个（eventToCombo/hasRequiredModifier/formatCombo）；cargo 125 / vitest 91 全过。

### 已知边界

- 录制期间 OS 级全局快捷键照常触发（按键拦截只到 webview 层）：录制与现绑定相同的组合会同时呼出对应浮层，属录制式改键固有限制。
- 回滚注册也失败（极罕见：旧组合在改键间隙被其他程序抢占）时，该动作的组合键标记未注册并在设置页警示，重新改键可恢复。

### 2026-10-14 — 缺陷修复：录制改走系统级键盘钩子（实机回归）

- **实机反馈**：Alt+Space 无法录入——按下弹出窗口系统菜单（截图），录制收不到。根因：Alt+Space（窗口系统菜单）、Win+E（Shell）等 OS 保留组合的 keydown 到不了 webview，基于 DOM keydown 的录制对这类组合必然失败。同理 RegisterHotKey 本身可行（已独立探测 MOD_ALT+VK_SPACE 注册成功）。
- **修复**：录制改经 WH_KEYBOARD_LL 低级键盘钩子（`platform/windows/record.rs`，`ShortcutRecorder` seam）：会话式截获（一个组合键 / Esc / 10s 超时），期间吞掉全部按键（系统菜单不再弹出，Win 单按也不开开始菜单）；VK→KeyboardEvent.code 映射纯函数 + 三态决策状态机（放行/吞掉/吞掉并结束）单测钉死。
- **排查中发现并修复本会话实现自身回归**：钩子回调曾把「吞掉」误当「结束会话」，Alt 按下瞬间会话即被取消——已改显式 enum 并补回归测试。
- **验证状态**：物理按键全链路（钩子截获 → 事件 → 前端修饰键校验）已在实机证实工作（调试期间实体按键被正确截获并送达）；keybd_event/SendInput 注入式自动化按键在本机被疑似 clash-verge 动态（卸）挂的键盘钩子间歇吞掉（无会话时注入可开系统菜单、会话中被吞且钩子收不到事件、物理键不受影响），注入驱动无法稳定完成自动化，最终以用户实体按键复验为准。
- **已知边界（新增）**：若其他软件在录制会话开始后（重）挂键盘钩子并吞掉按键，本次录制收不到键，10 秒超时取消——重新点「修改」再按即可（新会话重装钩子排到链头）。

### 2026-10-14 — 二次实机缺陷排查（录制全失效 + Alt+Space 仍弹菜单）

- **排查结论（实机验证）**：钩子链路本身在独立进程与真实 App 进程均实测工作——探针驱动 seam：钩子安装成功、注入按键被截获、outcome 正确交付；App 内自动开启的录制会话更截获了用户实体按键。「录不进任何键 + Alt+Space 弹系统菜单（= 钩子没在吞键）」的组合最可能来自**旧后端进程 + HMR 新前端的混合实例**：`shortcut_record_begin` 在旧后端不存在，invoke 失败即退出录制态。复测前必须彻底退出全部 Youmi 实例（single-instance 会复用旧进程）再重启 dev/重建。
- **修复一（真缺陷）**：修饰键态原先经 `GetAsyncKeyState` 读取——被钩子吞掉的按键不进系统输入管线，异步键表不更新，实机实测 `Alt+D` 被录成裸 `KeyD`（修饰键丢失 → 修饰键约束误拒）。改为 `Mods` 由钩子事件自行跟踪（按下/抬起），仅录制前已按住的修饰键以开始时刻异步键表为种子（`seeded_with` 可注入查询函数供单测）。回归测试钉死：alt+Space 截获、修饰键抬起清除、左右变体归一（alt+shift+super+Comma）、种子映射。
- **修复二（真缺陷）**：会话代数原先在会话结束后回退复用（None → 1），10s 内先完成一次录制再开新会话时，旧看门狗按同代误杀新会话（表现为第二行录制中途莫名退出）。改为 `NEXT_GENERATION` 全局单调递增，迟到看门狗不可能命中新会话。
- **修复三（可观测性）**：超时未截获与 Esc/主动取消此前同以 Cancelled 交付，前端无感退回录制行。`RecordOutcome`/`RecordEventPayload` 新增 `Timeout`，设置页超时提示「未截获到按键（可能被其他软件拦截）」——本机确有第三方键盘钩子（实测注入 Space 被改写为 F22）会整段吞键，该提示避免再被误判为「录制功能坏了」。
- **验证状态**：cargo 141 / vitest 88 全过，clippy/oxlint 干净；App 内物理按键（Alt+W）修复后录得 `alt+KeyW` 前缀正确。Alt+Space 录制与系统菜单抑制待用户以物理按键复验（注入通道在本机不可信）。

### 2026-10-14 — 二次复验仍失效的根因与轮询兜底修复

- **复验症状收窄**：用户清缓存重建后复测，超时提示能正常弹出（命令/事件/前端链路全通），但录制期内按键一个都截不到，且**按下的组合触发了其他软件的快捷键**——说明按键照常流入了系统，唯独我们的钩子收不到派发。
- **根因**：WH_KEYBOARD_LL 按「后装先叫」排队。本机存在会在录制会话开始后重挂键盘钩子的软件（上一轮已观察到动态挂/卸、注入键被改写为 F22 等），它排到我们前面把按键处理掉（吞掉或吞掉重注入并阻断回灌），我们的钩子从此收不到事件——链位是输赢关键，纯钩子方案在这台机器不可靠。
- **修复（轮询兜底）**：录制会话并行跑一个 `GetAsyncKeyState` 采样线程（15ms）：按「按下沿」截获可映射键，修饰键态 = 钩子事件跟踪态 ∪ 异步键表当前态（被钩子吞掉的键只有跟踪态知道、被抢位钩子截走的键只有异步键表知道）。异步键表在所有钩子之下，不依赖链位；钩子在前时先截获并吞键、异步键表不更新，轮询自然沉寂，两路以会话 active 位先到先得不会双报。Esc → Cancelled、不可映射键 → Cancelled，与钩子路径同语义；超时仍由看门狗交付 Timeout。
- **已知边界（更新）**：钩子被抢位期间按键无法吞掉——录制时其他软件的快捷键可能同时触发、Alt+Space 的系统菜单可能弹出（截获本身不受影响）；钩子被抢位且对方完全吞键不重注入时异步键表无沿可采，仍走 10s 超时并提示。
- **排查方法论备注**：探针验证受本机完整性级别干扰——agent shell 非提权进程，UIPI 下其 SendInput 被拒、GetAsyncKeyState 看不见提权窗口的输入；真实改键场景中按键去向是 Youmi 自己的设置窗口（与采样线程同进程同完整性级别），可见性有保证。复验必须以用户实体按键为准。
