# 01 — 浮层共存：三浮层焦点转移不互隐

**What to build:** 命令面板、剪贴板、划词翻译三个浮层可同时可见：焦点在浮层之间切换时不再把失焦的那个藏掉，用户在浮层之间往返不丢上下文；点击浮层以外区域仍全部隐藏；固定（pinned）语义不变。机制按浮层窗口类别统一，不做按窗口名的特判。

**Blocked by:** None — can start immediately

**Status:** done（2026-10-20 实机验收通过，含剪贴板回填修正复验）

- [x] 剪贴板浮层可见时呼出命令面板，两者同屏可见且各自可交互
- [x] 焦点在两浮层间往返，均不隐藏
- [x] 点击任一浮层之外的应用窗口，浮层照常失焦隐藏
- [x] pinned 固定的浮层行为不回归
- [x] 划词翻译浮窗同样适用（呼出命令面板不使其消失）

## Comments

### 2026-10-19 — 实现

- **机制**（`src-tauri/src/overlay.rs`）：新增 `OverlayRegistry`（浮层 label 注册表，`create` 时登记）；失焦处理不再立即 `hide`，改为 `schedule_family_blur_check`——延迟 150ms 后复查：家族内任一浮层持有焦点（含失焦窗口自己重新聚焦的呼起竞态）则全家保留，否则隐藏所有可见的未固定浮层。语义收敛为"浮层要么共存，要么一起退场"，pinned 豁免在同步段（不动）与复查段（跳过）都保留。
- **为什么延迟**：`Focused(false)` 不携带焦点去向；150ms 留足兄弟浮层 `Focused(true)` 落地，又短到肉眼无感。
- **连带语义**：快捷键主动收起某个浮层时，其失焦同样触发复查——无浮层聚焦时全家退场（主动关闭 = 家族退场，与点击外部一致）。已在 Rust 测试全绿（152 passed）。
- **验收方式**：浮层焦点行为需实机验证（多窗口焦点转移无法单测覆盖）。

### 2026-10-20 — 验收反馈修正：剪贴板条目回填命令面板输入框

实机发现：面板输入 `/t` 后快捷键呼出剪贴板浮层选中条目，预期回填 `/t {内容}`，实际输入框被置空。根因是两个既有设计在共存场景下的合成缺口：

- **回填通道缺失**：呼出剪贴板浮层时前台是面板浮层，回帖目标捕获把自家浮层记为无目标，选中条目走"仅复制"降级——内容只进剪贴板，什么也不发生。
- **focus 清空查询**：剪贴板浮层收起后焦点回落到仍可见的面板，面板在 window focus 事件里无条件清空输入。

修正：

- **回填**（`clipboard/pasteback.rs` + `commands.rs`）：回帖时命令面板可见且条目为文本 → 文本经 `palette-insert-text` 事件插入面板输入框光标处（新结果 `inserted-to-palette`），不写剪贴板、不模拟键击，剪贴板浮层收起、焦点交还面板；有效回帖目标存在时照常回帖，图片条目照常回帖/降级。
- **呼起重置**（`shortcuts.rs` + 面板前端）：清空查询从 window focus 挪到 Rust 呼起事件 `palette-reset`——共存后焦点从兄弟浮层回落不再清空，用户输入与回填内容都留得住；面板每次召起仍是新起点。
- 前端光标插入逻辑抽为纯函数 `insertAtSelection`（`lib/palette.ts`），Rust 回填分支 4 例 + 前端 5 例单测覆盖；回填链路端到端依赖真实窗口焦点，已实机复验通过。
